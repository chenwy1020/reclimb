# 0.4.1 实施记录

## 设计判断

直接永久删除把一次整理决定变成不可逆的数据损失，也不符合系统对长期学习过程的责任。0.4.1 因此采用 30 天“最近删除”：正常学习界面立即停止使用该项目，完整档案继续保留，恢复后沿原主线继续。

## 一致性与故障恢复

项目删除状态与能力状态分开。移入最近删除不会撤销或重判任何历史证据，只让它退出当前汇总。所有教学与材料入口在主进程再次拒绝已删除项目，避免仅依赖界面隐藏。

永久删除集中在一个服务中。每个材料目录必须通过本机工作区边界检查；文件先进入带项目和材料编号清单的暂存目录，数据库中所有项目关联再于一个事务内清理。数据库提交前异常退出时，启动或恢复操作按清单把文件放回；原目录冲突、路径逃逸或原件缺失会阻止项目恢复并保留现场。数据库提交后的诊断清理失败会留下持久完成标记，供下次启动重试。项目管理与仍可能发布记录的模型调用互斥。

## 迁移与交付

数据和备份格式升级到 6。旧数据库升级前保留精确副本；完整备份保留最近删除与材料，可读导出排除它们。桌面验收增加完整的删除、隐藏、恢复、再次删除和永久清理路径，全程不发起 AI 请求。

## 尚未改变的判断

删除功能解决资料管理，不是教学进步。项目数量减少、恢复成功或测试通过都不能作为学习有效性的证据；后者仍需通过跨日独立重构、迁移表现与帮助变化观察。
