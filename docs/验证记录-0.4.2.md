# 重登 0.4.2 验证记录

验证目标：修复模型切换难以核对与 DeepSeek 路线输出被思考 token 挤占的问题，并验证多个模型配置能够独立保存、切换、计费和备份。开发验证不使用私人教材、现有学习数据库、真实 API 密钥或真实付费调用。

## 日志诊断结论

对 0.4.1 本机诊断记录的只读检查确认：切换设置之后的新请求已经发送了新填写的 `deepseek-flash`，旧 Fireworks 模型只出现在更早的调用中。由于失败的新路线没有发布，界面继续显示旧路线，造成“仍在使用旧模型”的合理观感。0.4.1 只保存请求模型，没有保存服务商响应中的模型名，因此无法进一步证明服务端实际解析到了哪个模型。

近期 5 次路线操作共产生 10 次响应（含格式恢复），全部以 `length` 结束，没有一份通过结构校验或发布。它们共返回 75,002 个输出 token，其中 67,269 个为思考 token，约占 89.7%；每次首次响应的 6,000 个 token 全被思考占用，正文为空。最后一次 9,000 token 的恢复中仍有 6,344 个思考 token，只留下不完整 JSON。该证据支持“可见输出被思考过程挤占”这一根因，不支持把失败归咎于学习者或材料内容。

## 离线验收范围

- 旧单模型设置升级为默认模型配置，活动配置继续对应原接口、模型、价格和密钥。
- 多配置新增、编辑、独立密钥、名称去重、启用状态、切换、删除限制及最多 20 项的边界。
- 未配置密钥的项目不能被设为当前；模型操作刷新界面时，尚未保存的预算、视觉设置和学习偏好不会被覆盖。
- 设置页测试非当前配置时不改变当前选择；顶部切换不发起模型调用。
- 每项新操作读取最新活动配置；已经预留或进行中的操作固定使用发起时配置。
- 调用记录与诊断分别保存配置、请求模型和服务商报告模型；服务商不报告时不推断。
- 视觉识别调用使用独立归因，不借用当前教学模型名称；已有凭据文件无法解密或损坏时，保存新密钥会保留原文件并停止写入。
- DeepSeek 官方接口的结构化请求关闭思考输出；Fireworks 上已识别的 DeepSeek 模型采用有界思考预算；其他兼容服务不附加未知厂商字段。
- 路线首轮可见输出上限提高到 9,000，单次恢复最高 12,000，并移除材料对象中重复的章节定位数组；超过 2,000 项的全局章节索引按材料均衡取样，首尾材料都不会因简单截断而消失。
- 路线 JSON 中缺失或循环的先修关系、能力／单元错绑及改变含义后错误复用旧身份会触发一次结构修复；最终无法发布和生成期间已过期的结果都会退出“待发布”。
- 数据库格式 6 到 7 升级前备份；备份格式 1 至 7 可读，格式 7 完整往返模型元数据与调用审计字段，所有密钥继续排除。
- 旧 `settings.save` 中夹带密钥的调用会被拒绝，避免用过时的接口信息错误绑定新密钥；第 21 项模型配置在写入凭据前即被拒绝。
- 恢复事务覆盖三个合法回滚阶段、非法路径与路径冲突、活动凭据冲突、日志删除失败后的重启续办，以及恢复期间所有并发界面请求的阻断。
- 开发版与安装包桌面流程覆盖新增配置、测试、快速切换、发起请求及请求/报告模型显示，并断言无外部请求。
- 构建前拒绝链接式或缺失的直接运行依赖；解包后核对 `app.asar` 中八项关键运行清单与 Windows canvas 二进制，再启动成品执行桌面流程。

## 仍然不能证明的内容

离线测试能证明应用按所选配置组织请求、记录审计字段，并处理已复现的长度问题。它不能证明第三方服务一定遵守模型名称，也不能证明路线内容正确、难度合适或促进了长期掌握。服务端实际模型只有在对方响应明确返回 `model` 字段时才可展示；教学有效性仍需用跨日独立重构、迁移表现和帮助变化检验。

模型配置的密钥文件与 SQLite 元数据分别原子落盘，但进程若恰在两者之间被强制终止，该项配置的密钥可能需要重新填写。现有绑定校验会阻止密钥串用，不影响学习档案；用凭据写前日志消除这一极小中断窗口，列为后续可靠性工作。
