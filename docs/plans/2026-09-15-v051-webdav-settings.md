# 重登 0.5.1：同步初始化与折叠设置

目标：让已保存的同步连接能明确重新编辑，消除首次读版本先于建目录的阻断，将设置功能卡片默认折叠。沿用用户授权直接修复、针对性验收与私有预发行交付。

现状：用户配置已保存且没有上传或共同版本记录；旧诊断只有教学调用，没有保存 WebDAV 响应。源码中 check 直接 GET head，MKCOL 仅在 upload 后段；目录不存在返回 409 时界面没有上传机会。本机隔离复现中旧原生 details 可以展开及填入名称，尚不能证明所有“无法修改”由 React 重绘引起；改为显式按钮与编辑状态，避免隐藏入口与隐含状态。

## 实施

1. 在 tests/webdav-sync.test.ts 用具备真实父目录规则的本机模型复现 409，检查首次目录准备、持续冲突、配置目录不存在和原有快照保护。检查时只建立应用子目录，上传仍需明确操作；不把任意 409 当空目录。
2. src/main/webdav-sync.ts 在首次检查的 409 后准备目录再读，正常已有版本保持只读；上传将 directories 提前到读版本之前。补充 409、权限与配额错误的处理建议，保留条件写入、原操作重试与源档案验证。
3. WebDavSyncPanel 显式“修改连接／收起连接编辑”，保存成功清理密码输入、更新状态；收起保留未保存文本，修改端点仍需新密码。状态读取失败可本机重试。
4. 新 SettingsCard 以按钮、aria-expanded/controls 和隐藏但保持挂载的内容实现默认折叠。用于外观、模型、视觉、费用、节奏、同步、最近删除、诊断及备份。卡片状态只存在当前页面，不进入档案或模型。
5. 新桌面组覆盖所有默认关闭、鼠标/键盘展开、输入保留、重新配置/重启、首次上传与持久 409、无 AI 调用、明暗和窄窗布局。将旧累计桌面组的设置导航改为正常点击展开卡片，纳入下次大版完整套件。
6. 发布范围限制为同步、相关备份保护、设置与交付脚本测试；执行类型检查、构建、包内新桌面组。小版本不跑全量。交付 0.5.1 安装包、源码、说明和 SHA256；不使用真实模型或上传私人档案。

协议依据：RFC 4918 §9.3/9.3.1 要求 MKCOL 的祖先集合存在，缺失时返回 409；本版按父目录顺序创建应用目录，并保留建好目录后仍返回 409 的错误，不放行冲突。
