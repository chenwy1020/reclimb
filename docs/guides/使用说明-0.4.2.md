# 重登 0.4.2 使用说明

运行 `Reclimb-Setup-0.4.2.exe` 并选择安装目录。升级前先退出旧版重登。首次打开既有档案时，程序会在资料目录的 `upgrade-backups` 中保存升级前数据库，再升级到数据格式 7；材料、路线、作答、争议、理解稿和能力证据继续保留原有关联。

## 保存多个模型配置

进入“设置—模型配置”，可以为不同服务或同一服务的不同模型分别保存：

- 便于辨认的配置名称；
- 服务名称、接口地址和准确的模型名称；
- 该配置单独使用的 API 密钥；`单次回复上限`按服务商给该模型的限制填写，路线生成和格式恢复都不会超过它；
- 输入、输出价格及核对日期。

点击“新增模型配置”建立新配置。编辑已有配置时，只要接口地址不变，密钥留空表示继续使用原密钥；修改接口地址时必须同时重新填写密钥。每项配置都可以单独测试连接；测试不会把它自动设为当前模型。当前配置不能直接停用或删除，请先切换到另一项。系统最多保存 20 项模型配置。

模型名称应按服务商文档准确填写。DeepSeek 官方接口当前使用 `deepseek-v4-flash` 与 `deepseek-v4-pro` 等名称；旧配置中的模型名会原样保留，软件不会擅自改写为另一个模型。

## 切换下一次请求使用的模型

应用顶部显示“下一次请求使用”。从这里选择配置后，之后新发起的路线、教学、反馈或评价请求会使用该配置；设置页的“设为当前”具有相同效果。切换本身不调用 AI，也不产生费用。

已有路线、讲解和作答属于产生它们时的内容版本，不会因为切换模型而改写。正在进行的调用会固定使用发起时的配置，完成后才允许切换，避免一项操作在中途混用两个模型。若要比较模型，应在保留原内容的前提下明确发起一次新生成或修订。

## 核对实际使用的模型

“设置—费用与边界—查看本机调用记录”会分别显示：

- 配置名称；
- 请求模型，即应用发送给服务商的模型名；
- 服务商报告模型，即服务商响应中的模型名。

诊断预览也保留这三项信息。部分兼容接口不会返回实际模型，此时会明确显示“服务商未报告实际模型”，而不是用请求模型冒充服务端结论。0.4.1 以前的调用没有保存这些字段，会显示为旧版记录。

## 路线生成达到长度上限时

0.4.2 会针对结构化路线控制 DeepSeek 的思考输出，给路线正文保留更多空间，并减少重复发送的章节定位信息。首次生成仍不完整时，程序最多进行一次格式恢复；恢复也会计入本机预算。任何失败都不会覆盖已有路线，草稿和学习记录继续保留。

如果仍出现长度上限提示：

1. 在设置中确认模型名与接口地址来自同一家服务商的当前文档。
2. 查看调用记录中的请求模型、服务商报告模型和输出 token。
3. 在诊断预览中确认结束原因；导出前留意其中可能包含学习内容。
4. 可切换到另一项已测试的模型配置，再明确重新生成。切换不会自动重复付费请求。

## 密钥、备份与费用

每项教学模型的密钥由 Windows 系统能力加密，并与该配置及接口关联。完整备份保存配置名称、接口、模型和价格信息，不包含教学或视觉服务密钥；恢复后需在本机重新填写密钥。

所有配置共用本机月预算。每次调用按发起时配置的价格预留费用，格式恢复也计费；最终费用以服务商账单为准。0.4.2 的开发验收使用自制材料和本机模拟服务，没有发起真实付费模型调用。

项目的“最近删除”、完整备份与恢复方式沿用 0.4.1。模型切换只改变请求来源，不改变能力证据的准入条件，也不证明教学内容正确或学习者已经掌握。

恢复档案时，程序会暂时阻止其他页面继续读写。如果恢复被断电、文件占用或异常打断，请重新启动重登；程序只会在能够证明旧档案已完整恢复或新档案已完整提交后重新开放学习空间。状态仍不明确时会保留现场并停止访问，不会自行拼接档案与密钥。
