# 重登 0.4.4 验证记录

## 真实故障与机制修复

对本机最近两次路线操作的四份诊断进行只读核对：四次均以 `stop` 结束，不是长度截断。失败包括能力先修字段中填入自然概念或简称、单元先修字段中混入能力名称、来源数量超过上限，以及回复中混入 JSON Schema。原响应仅在本机检查，未用于外发开发测试。

代码中的关系校验位于 Zod 的 `superRefine`，不会自动成为给模型的 JSON Schema 关系约束；原提示“列出先修”没有说明引用种类。恢复只带前三条摘要，不带失败候选，因此新生成反而可能破坏原来的正确部分。

本版在输出结构描述和请求中明确三类引用、历史 ID 与输出标题的区别，并提供一个原创局部示例。外部基础进入现有单元 `unresolvedGaps`，继续保持未知。引用错误列出具体错误值与可用目标，来源、循环和旧身份校验维持原准入。

格式恢复附带最多 65,536 字符的原失败响应、最多 40 条结构化问题；问题消息与总长度有界，显式标记截断和遗漏。每条费用预留按实际序列化请求计算。候选和错误说明只作为待修数据，要求输出结果对象，不复述格式说明。自动恢复仍最多一次，语义校验未通过的内容不会发布。

## 验收范围

- 能力外部基础、单元误用能力名称、地图引用及来源超限均有可定位错误。
- 原候选与第三条之后的问题进入恢复请求；修复后保留外部缺口，能力证据数量不变。
- 调整路线时明确历史 ID 与输出标题，旧能力及单元身份不能被随意改绑。
- 超长响应、40 条问题及总长度边界、逐项截断、夹杂 Schema、恢复预算不足、第二次失败均有离线回归。
- 桌面流程包含一次故意混淆两类引用的首次生成，验证随后定点修正、缺口可见、失败结果退出发布状态。

离线执行结果：58 个测试文件、460 项测试全部通过；类型检查及构建通过。新增 11 条路线与恢复回归先复现失败，再修复通过。开发桌面 77/77 项通过，48 次请求全部发往本机模拟服务。独立只读代码审查未发现本次修复范围内的 P0–P2 阻断。

源码白名单与常见凭据标记检查覆盖 190 个文件，未发现违规；该检查不等同于通用秘密扫描器。数据库及备份格式保持 7，不批量修改原档案。

安装包解出成品通过运行依赖核对及 77/77 项桌面检查，48 次请求全部使用本机模拟服务，外部请求为 0。安装包大小为 146,050,865 字节，SHA-256 为 `e42196ad1999a7ac138b43a63edd7ca90e5067b0ba92a7f5862292d0755d93dd`。机器报告为 `package-verification-v044.json`，源码与安装包交付由 `delivery-v044.json` 及 `SHA256SUMS.txt` 核对。

## 真实模型验证与边界

使用原开发累计账本核对余量，遵守已授权累计上限，并设本轮固定额度；重复运行不能重置余量。个人历史费用与账本仅在本机保留。只发送自编数学推理与论证表达概要，不发送私人教材、学习记录、诊断原响应或用户偏好。密钥仅在内存读取，未输出到报告或备份；日常学习预算不变。

2026 年 9 月 12 日真实验证通过：两份原创材料分别生成包含 6 项能力、6 个学习单元的路线，均在首次调用通过严格引用与来源校验并保存；能力证据仍为 0。服务商报告模型与请求模型均为 `deepseek-flash`，结束原因均为 `stop`。这两次未触发恢复；故意错误后的恢复由离线和桌面回归验证。

采用开发保守估算价（输入 3 元、输出 10 元／百万 token）记录这两次原创验收费用 0.086514 元，已在本机累计账本内入账且未超出授权余量；服务商实际费用以账单为准。私人原始诊断只在本机排查，没有发给模型。个人测试脚本、凭据、本机报告与费用账本未加入源码交付。

即使路线通过结构校验，也不能证明每个教学判断正确、挑战难度合适或已经产生学习效果。成品桌面验收运行安装包解出的程序，不执行安装向导，不代表全新 Windows 安装验收。
