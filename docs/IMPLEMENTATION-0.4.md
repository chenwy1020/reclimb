# 0.4 实施记录

## 被修正的管理错误

0.3.1 的“近期几步”没有稳定进度身份，“继续”主要围绕当前能力换题，讨论中的表现也很难改变后续选题。结果是路线像目录，学习者可能在已经会的简单操作上循环，路线重新生成还会切断部分位置关系。

0.4 以路线版本、学习单元和主线位置替代静态建议。首次路线依据完整目录与页段索引建立粗图，正文分批读取并标记覆盖范围。路线调整先成为不可变提案；采用时复用稳定单元编号，旧会话、作答和理解版本继续关联原记录。

推进器读取任务级观察、有效证据、帮助、争议、纠正与理解稿。两次同类同层操作后，默认提高要求、前进或指出具体缺口。挑战带有可检查的认知要求；未完成挑战只补实际缺口。主动跳过会移动主线，但不写掌握证据。

## 读厚、读薄与来源阅读

理解稿采用追加版本，分别标记学习者原述、AI 建议和学习者修改 AI 建议。读厚与读薄可以在单元内往返；AI 内容进入答案暴露历史，不冒充独立重构。

PDF 原始提取从 Markdown 渲染链中移出。可靠原生正文只做纯文本断行整理；OCR 或公式可疑页面展示原图，整页或局部人工确认产生新的阅读布局和来源版本。AI 取材与阅读界面共享确认版本选择规则。

## 实施中发现的新回归

窗口验收发现：旧项目在启动迁移时被写入当前时间，会抢占首页“继续上次学习”，使最后草稿保存到了并非用户预期的项目。迁移现沿用项目与会话的历史更新时间，只建立结构关联，不制造新的学习行为时间。新增回归测试和即时关窗桌面检查覆盖该问题。

交付前审查补上了连续推进的边界：路线调整以显式且不可改写的身份保留仍相同的能力；只有核验通过、达到全部适用要求且不处于待复核状态的不同表现可以触发自动加难；路线或主线改变后丢弃迟到的活动生成；缩小一步不会被误记为挑战；确认原题可用后恢复被暂停的有效观察；多个已确认选区共同进入阅读布局；片段内前进和支线返回都会更新首页位置；退出当前路线的旧会话必须重新定位。格式 5 备份保留这些推进条件，并校验主线确实属于项目当前路线。

## 保留的限制

全书粗图不是整本正文的一次性总结；尚未读取的部分必须明确保持待深入。活动难度元数据与模型审查只能排除部分伪进阶。无法可靠恢复的数学公式继续以原页为准。跨日独立表现和帮助变化仍是学习有效性的主要证据。
