# 重登 0.4.3 验证记录

## 根因与修复范围

用户截图的 `profile.maxOutputTokens Too big: expected number to be <=131072` 来自本机结构校验。0.4.2 在模型配置、常规设置、存储规范化及输入控件中重复使用 131,072，导致填写更大值被拒绝，即使只修改前端也会在重启或恢复时丢失该值。

本版把最小值 512、最大值 393,216 及默认值 12,000 定义在共享模块，设置、存储、备份校验与界面共同使用；输入步长改为 1。默认输出和任务输出策略保持原值，不把模型容量直接用作请求或费用预留数量。

本次核对 [DeepSeek 官方接口](https://api-docs.deepseek.com/api/create-chat-completion/) 明确允许 `max_tokens` 1 至 384K（393,216）；[模型页](https://api-docs.deepseek.com/quick_start/pricing/) 当前名称为 `deepseek-flash`，旧 `deepseek-v4-flash` 为兼容映射。软件仍允许配置其他服务，填写值需要遵守相应服务商限制。

## 验收范围

- 384,000 与 393,216 通过实际设置入口，保存、重启及备份恢复后保持原值。
- 小数、非有限数、低于 512 及超过 393,216 被拒绝，错误信息为中文。
- 旧配置缺省值仍为 12,000；较低配置上限继续限制请求和修复。
- 大容量配置仍以任务实际请求长度预留费用，零预算不发起调用。
- 桌面检查覆盖 384,000、393,216 及 393,217 三个用户操作，保留 0.4.2 的 73 项有效检查。
- 打包前检查真实运行依赖，成品解包后检查依赖与桌面流程；源码按白名单归档，检查远程发布附件散列。

2026 年 9 月 12 日执行结果：56 个测试文件、448 项自动化测试通过；类型检查及构建通过。新增 14 项回归中，修复前有 11 项失败，修复后全部通过。独立只读代码审查未发现 P0–P2 问题。

开发版与安装包解出成品分别通过 76/76 项桌面检查，各使用 46 次本机模拟请求，外部请求为 0；成品运行依赖核对通过。安装包大小为 146,048,888 字节，SHA-256 为 `d1842fae01927899b5b0dc33771d4a4624e13d0229d8091f163840bebad76c07`。机器记录分别写入 `desktop-verification-v043.json`、`package-verification-v043.json` 和交付清单，发布附件通过散列比对。

源码白名单及常见凭据标记审计覆盖 183 个文件，未发现违规；此检查不等同于可以发现一切秘密的通用扫描器。本轮不使用私人教材、学习档案或真实 API 密钥，不发起真实付费模型调用。

## 验证的边界

桌面验收运行从安装包解出的应用，不执行安装向导，也不代表全新 Windows 安装验收。模拟请求验证设置与请求、费用逻辑，未要求真实 DeepSeek 生成 384K 输出。保留的数据格式仍为 7，没有改写旧证据或批量迁移配置。旧版软件不能恢复新版的高上限配置。
