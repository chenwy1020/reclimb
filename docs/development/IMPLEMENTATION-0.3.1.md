# 0.3.1 实施记录

## 问题与结果

旧界面把能否进行能力评价作为能否提交作答的条件。题目来源有疑点时，学习者的作答只能留在草稿，且界面不能解释核验受阻的具体原因。

0.3.1 将保存与回应分为两次调用。记录输入时冻结题目、步骤、作答与当时帮助条件；回应时根据冻结的反馈模式进入评价或讨论。讨论只产生交流记录，不自动补发能力评价。忙碌期间可保存，但不自动产生下一笔请求。

## 必须保留的边界

- 旧 `session.submit` 复用新流程，兼容现有调用。
- 成功反馈及完成状态在同一事务提交，失败重试不重复成果。
- 迟到反馈关联原作答；评价写入前再次检查争议和版本。
- 来源确认建立新版本；同一未变内容复用已有核验，只读重试不收费。
- 数据格式与备份升级到 4，不增加集合，不批量重新评价历史证据。
- 主设置入口保留，删除侧栏底部重复卡片。

## 交付方式

私有 GitHub 仓库保留整理后的 0.3 基线，通过修复分支和 PR 交付。源代码采用文件白名单，不包含教材、用户档案、私人诊断、凭据和个人调用账目。自动化桌面测试默认生成原创 PDF；Windows CI 不使用真实模型密钥。

具体已执行验证与限制见《验证记录-0.3.1》。本记录是工程说明，不是学习有效性证明。
