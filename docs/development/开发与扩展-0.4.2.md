# 重登 0.4.2 开发与扩展

0.4.2 将教学模型从一组全局字符串改成可持久化的 `ModelProfile[]`。每项配置拥有稳定 ID、名称、服务名称、接口、模型名、价格和启用状态；`activeModelProfileId` 表示下一次新请求使用哪一项。为兼容已有教学与费用代码，`Settings` 顶层的服务、接口、模型和价格始终投影为当前配置的值。

## 模型配置与调用边界

主进程提供以下操作：

- `settings.modelProfile.save`：新增或更新配置，可同时写入该配置的密钥；
- `settings.modelProfile.activate`：改变之后新请求的活动配置；
- `settings.modelProfile.test`：用指定配置测试连接，不改变活动配置；
- `settings.modelProfile.remove`：删除非当前配置及其密钥。

配置写入由 `ModelProfileManager` 统一校验。名称在忽略大小写与首尾空格后不能重复；当前配置不能停用或删除；至少保留一个启用项；教学或视觉调用可能发布结果时拒绝更改配置。

`CallRunner` 在操作开始时冻结设置、密钥和模型配置元数据。预算预留也保存该上下文，随后切换活动配置不会改变已经预留的操作。费用记录同时保留 `modelProfileId`、`profileName`、`providerName`、`requestedModel` 和可选的 `reportedModel`。提供方响应顶层 `model` 字段只作为服务商报告值保存，不覆盖请求值。

## 密钥与迁移

教学密钥文件升级为加密的 v2 映射：每个条目在同一受保护载荷中保存配置 ID、接口绑定和密钥。旧版单密钥仅可供迁移出的默认配置读取；首次写入新配置时会一并转入 v2。即使两个配置使用相同接口，也可以保存不同密钥。

SQLite `user_version` 与 `.reclimb` 备份格式均为 7。格式 6 及更早的全局模型设置迁移为 `default-model`；升级前保留 `pre-0.4.2-*.sqlite`。格式 1 至 7 的备份继续可读。备份移除所有密钥及 `hasApiKey` 状态；传给界面的公共快照只包含用于显示“已配置／待配置”的布尔状态，不包含密钥本身。恢复后这些状态由本机凭据重新计算。

## 提供方适配

结构化输出仍按接口能力选择格式：Fireworks 使用 JSON Schema，DeepSeek 官方接口与通用兼容接口使用 JSON object。思考参数只在已识别的提供方上发送：

- DeepSeek 官方接口的结构化教学请求发送 `thinking: {type: "disabled"}`，避免思考 token 用尽路线正文额度；
- Fireworks 上已识别的 DeepSeek Flash 系列在长结构化请求中使用 2,048 token 的有界思考，短连接测试关闭思考；
- 未识别的兼容接口不发送 DeepSeek 或 Fireworks 私有字段。

扩展新的模型提供方时，应在提供方适配层明确声明结构化格式和思考控制，不能根据模型名的模糊包含关系向未知接口发送专有参数。若服务商返回响应模型名，应映射到 `reportedModel`；缺失时保持未报告。

## 路线生成

路线首轮输出额度为 9,000 token，格式恢复按既有规则最多一次并封顶 12,000 token。路线输入继续保留全局 `sectionIndex`，不再在每个材料对象内重复 `sectionLocators`。索引最多发送 2,000 项，并按材料分别保留首项、末项和分布在其间的条目，避免按原数组截断时只留下前一本材料；请求同时标明已纳入和未纳入的数量。来源版本与路线结构校验继续保留。

能力和学习单元的名称唯一性、先修引用、先修环、单元到能力的对应，以及旧能力／旧单元身份复用都由 `routeSchemaFor` 在调用仍可恢复时检查。没有显式旧编号时，身份推断会递归确认所有先修仍指向原身份。通过模型校验后至数据库发布前的并发变更或存储错误由 `generateRoute` 统一把该次结果标为丢弃。来源归属校验保持独立且严格，不将项目外引用当作可以自动改写的普通格式错误。

## 恢复事务边界

完整恢复会在第一次异步文件操作前关闭新的界面请求。恢复日志只接受三种可证明的交换阶段；任何路径不在本次资料目录、路径相撞、文件状态含糊或凭据冲突都会停止恢复，不移动现有档案。回滚必须明确回到旧档案后才重新开放界面；提交完成但日志暂时无法删除时，本次运行继续阻断，重启后只执行可证明安全的提交清理。

## 本地验证与交付

```powershell
npm ci
npm run typecheck
npm test
npm run build
npm run test:desktop
npm run package
npm run verify:package
npm run package:source
node scripts/verify-delivery.mjs
```

`scripts/release-contract-v042.json` 是 0.4.2 安装包与源码交付共同读取的桌面检查契约。增加或删除桌面断言时，要在审阅具体报告后同步更新其中的 `expectedChecks`。常规验证只使用隔离资料目录、自制材料和本机模拟服务。

`scripts/check-package-input.mjs` 在构建前拒绝缺失、无版本或链接式直接运行依赖；`scripts/verify-packaged-dependencies.mjs` 在安装包解包后核对主进程依赖与本机图形二进制。两项通过后仍运行完整桌面验收，不能用静态文件存在代替真实启动。
